## Design workflow and limits

When Gemini is configured, Studio selects its planning step by default. The owner
can choose local composition. A Gemini request creates a durable, snapshot-bound
run. Structured output is validated before a bounded layout/alignment change is
applied; real logos, product images and copy remain intact. The design idea and
image prompt are displayed and included in the ZIP export. A changed price,
profile, preference, image or input invalidates the direction before composition.

This is Gemini text planning followed by local image composition. It does not
enable an image-generation API or create a new product photograph from the prompt.
The uploaded photo and logo are represented by metadata/palette, not sent as image
pixels for Gemini vision. Design ideas are mapped to three supported layouts;
arbitrary art direction is retained as advice/prompt, not executed as scene code.

Each creative run uses a fresh Hermes process/home, no tools, one model turn, no
provider fallback and no automatic write retry. Budget is conservatively reserved
before transport; observed usage is recorded separately. Duplicate clicks reuse
an active/completed request; an explicit retry can create a new request after a
failure/cancellation. Cancellation and timeout preserve the original design.
Expired exhausted leases require review and are not resent.

Gemini-free input needs public-data attestation and still passes classification;
detected private/credential/contact content is rejected despite attestation.
Pattern classification cannot establish that arbitrary prose is public. Operators
must supply only permitted business data; raw customer records and documents do
not belong in this workflow.
